Terrain and earthworks from a survey or a height model, point clouds of billions of points, one coordinate system for everything, and a page that stays responsive with large models.

### Terrain and earthworks
- **Height models as GeoTIFF (#92).** Drop a `.tif` such as a DHM/Terræn tile: it opens as a terrain, cut to the models and placed in map coordinates.
- **A ground filter (#92)** builds a terrain from a point cloud without classes. It removes trees, buildings and vehicles first.
- **Contours (#92)** in 3D and in plan drawings (DXF layer `CONTOURS`), every 5th one thicker and with its height.
- **Cut and fill (#92):**
  - the terrain against the embankment, along an alignment;
  - key figures, a table per station range, a CSV and a difference map in 3D (red: cut, blue: fill).
- **LandXML export** of a terrain, for Civil 3D, Novapoint, Trimble and others.

### Point clouds
- **COPC (#52).** Cloud-optimised LAZ is read piece by piece, never whole:
  - more detail where you look, within the point budget;
  - sections and longitudinal profiles load the points along them at full density.
- **E57 (#52)** from terrestrial scanners: all scan positions, placed with their poses.
- **Depth shading (EDL)** for dense clouds without colours.
- **Clouds in projects and workspaces.** Up to 300 MB they are stored with the project. Larger ones are opened again from where they are (Chrome/Edge).

### Coordinate systems
- **One project coordinate system (#107)**, chosen at the top of the model browser.
  - Models, clouds, GeoTIFF and LandXML in another system are converted into it on the fly: UTM 32N/33N, DKTM1–4, Kp2000, Gauss-Krüger, DB_REF or any EPSG code.
  - The system is read from the files or chosen on the card. Heights are not converted.
- **Alignments with a placement of their own** are now placed correctly.

### Large models
- **IFC geometry is built in a worker (#58).** Opening the 26 MB Chesapeake sample blocked the page for 2.1 s; now 1.0 s.
- **Long models draw only what is in view (#60).** Close up on a 31 km corridor, 72 % fewer triangles.
- **Filters start without freezing the page (#61),** and the index is kept for next time: 4.6 s → 1.6 s, then 0.15 s.
- **Autosave** no longer stutters on large models.
- **Colours and selection** no longer send the whole model to the graphics card again: a filter colour on Chesapeake 16.8 MB → 4.1 MB, a selection 0.57 MB → nothing.
- **The picking index is built in the worker** and kept with the geometry: 1–2 ms on the main thread instead of 106–170 ms.
- **The start screen loads 1.5 MB of JavaScript instead of 4.9 MB:** the IFC library comes with the first model.
- **An idle view is not drawn again**, and depth shading (EDL) needs a third less graphics memory.

### Easier to use
- **Accessibility (#62).**
  - Menus and tabs work with the keyboard and screen readers.
  - Contrast and click targets meet WCAG 2.2 AA.
  - axe-core checks it on every pull request.
- **Floating panels** can be moved by their header. The **view cube** replaces the axis cross (#95).
- **Cross sections show all alignments they cross**, each named with its track and station, and **top of rail** is annotated.
- **The cut and fill and drawing dialogs** are laid out in two columns (#96).
- **The welcome screen on phones** fits the screen.
- **The installed app** is called just "Vispecta".

### Privacy and security
- **A Content Security Policy (#64).** The browser enforces that the pages load only from vispecta.com and contact no other server than the GitHub API (update check) and epsg.io (a coordinate system you look up).
- **A bounded offline cache.** Samples and the Python runtime are cached only once used, and under 250 MB.
- **Files from others are checked more strictly:** BCF files cannot unpack to gigabytes, workspace files give only well-formed views and issues, and drawing presets set only their own fields.
- **A Python runtime override** (an intranet mirror) must be https: or the site itself, and the About dialog says when one is used.

### Fixes
- A point cloud could be missing when a project was opened again.
- Closing a project now resets its coordinate system.
- The popped-out section window had no fonts.
- Station labels in 3D were hard to read (white on orange).
- A model converted vertex by vertex into the project's coordinate system was converted twice when the project was opened again.
- A file that failed to load kept its memory until the page was reloaded.
- A COPC cloud could wait for ever when its worker stopped.
